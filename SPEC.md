# Спецификация: трекер подготовки к интервью

Личное веб-приложение для одного пользователя. Показывает 16-недельный план подготовки к интервью UI-инженера, ведёт прогресс, повторения, заметки, стрик и призы.

Весь план лежит в `plan.json`. Приложение его только отображает и хранит поверх него состояние пользователя. Содержание плана в коде не дублируется.

## 1. Цели и границы

**Нужно:**

- Каждый день за 5 секунд видеть, что делать сегодня, со ссылками.
- Отмечать сделанное одним действием.
- Видеть очередь повторений и способ повторения для каждой задачи.
- Видеть прогресс недели, стрик и ближайший приз.
- Оставлять заметки к задачам и дням.
- Листать недели и смотреть календарь на все 16 недель.

**Не нужно в первой версии:**

- Авторизация, бэкенд, синхронизация между устройствами.
- Редактирование плана из интерфейса (план правится в `plan.json`).
- Уведомления, темы оформления сверх светлой и тёмной, аналитика.

## 2. Стек

- React, TypeScript, Vite. Маршрутизация: React Router.
- Tailwind CSS.
- Состояние: Zustand или контекст с редьюсером, на усмотрение исполнителя.
- Хранение: `localStorage` через интерфейс `StorageAdapter` (`load`, `save`, `export`, `import`). Интерфейс нужен, чтобы позже подключить удалённое хранилище без переписывания логики.
- Тесты: Vitest для модуля правил (раздел 6). Интерфейс тестами не покрывать.
- Деплой: Vercel, статическая сборка.
- Интерфейс на русском. Адаптивная вёрстка, телефон обязателен.

## 3. Данные плана: `plan.json`

Файл только для чтения. Положить в `src/data/plan.json`, типы описать в `src/data/types.ts`.

| Поле | Содержание |
| --- | --- |
| `meta` | Название, `startDate` (понедельник первой недели), число недель |
| `blocks` | Словарь: код блока → русское название |
| `phases` | Словарь: код фазы → русское название |
| `rules` | Числовые параметры правил повторения и призов |
| `weeks[]` | 16 недель |
| `items[]` | Все отслеживаемые задачи |
| `maintenanceWeek` | Шаблон недели после окончания плана |
| `mocks[]`, `stories[]`, `applications[]` | Заготовки журналов |
| `resources[]` | Список платформ |

**Неделя:** `n`, `phase`, `title`, `webTopic`, `prize { title, tier }`, необязательный `checkpoint`, `days[]`. Значения `tier`: `small`, `big`, `final`.

**День:** `dow` (1 это понедельник), `offset` (сдвиг от начала недели в днях), `lightAlternative` (текст лёгкой замены), `sessions[]`.

**Сессия:** `id` (уникален, вид `w03-d6-s1`), `minutes`, `block`, `title`, необязательные `itemId`, `links[]`, `optional`.

**Задача (item):** `id`, `kind` (`dsa`, `js`, `ui`, `fe-sd`, `be-sd`), `title`, `week`, `difficulty`, `topic`, `links[]`. Если `userNamed: true`, то `title` пустой: название пользователь вписывает сам, подсказка лежит в `hint`.

**Ссылка:** `label`, `url`, `confidence`. Значение `checked` означает проверенный адрес, `pattern` означает адрес, собранный по шаблону сайта (см. раздел 8).

Дата дня считается так: `startDate + (week.n - 1) * 7 + day.offset`.

## 4. Состояние пользователя

Один объект в хранилище под ключом `prep-tracker-state`, с полем `version` для миграций.

```ts
type Outcome = "clean" | "hint" | "failed";

interface UserState {
  version: 1;
  startDate?: string;                    // переопределяет plan.meta.startDate
  items: Record<string, {
    title?: string;                      // для задач с userNamed
    attempts: { date: string; outcome: Outcome }[];
    keyIdea?: string;                    // ключевая идея одной строкой
    note?: string;
  }>;
  sessions: Record<string, { status: "done" | "light" | "moved"; date: string }>; // date: когда поставлена отметка
  dayNotes: Record<string, string>;      // ключ: дата YYYY-MM-DD
  sessionNotes: Record<string, string>;  // заметки к ручным сессиям; у сессий с задачей заметка в items[id].note
  prizesClaimed: Record<number, string>; // неделя → дата получения
  mocks: { week: number; type: string; date?: string; notes?: string }[];
  stories: { topic: string; situation?: string; ready: boolean; result?: string }[];
  applications: { company: string; status: string; referral?: string;
                  appliedOn?: string; nextStep?: string; notes?: string }[];
}
```

Русские подписи исходов: `clean` это «Сам», `hint` это «С подсказкой», `failed` это «Не решил».

## 5. Экраны

### 5.1 Сегодня (главный)

- Дата, номер недели, фаза, тема недели.
- Список сессий дня: минуты, блок, название, кнопки ссылок, отметка.
- Очередь повторений на сегодня: задача, способ («Устно, 3-5 мин» или «Решить заново»), кнопки исхода.
- Плашка «Если устал» с текстом `lightAlternative` и кнопкой «Отметить день лёгким».
- Прогресс недели, стрик, приз недели и сколько сессий до него осталось.
- Поле заметки дня.
- До даты старта: обратный отсчёт. После недели 16: шаблон `maintenanceWeek`.

### 5.2 План

- Переключатель недель 1-16, текущая выбрана по умолчанию.
- Шапка недели: фаза (цветом), тема, приз, статус «закрыта или нет», контрольная точка, если есть.
- Переключатель дней недели (7 вкладок). На вкладке процент выполненных обязательных сессий дня и цвет статуса.
- Над сессиями итог дня: статус, прогресс и, для прошедших дней, список невыполненного.
- Под каждой сессией заметка. Вход по `?day=дата` открывает эту неделю и этот день, без параметра открывается сегодняшний день, для другой недели понедельник.
- На кнопках переключателя недель и в шапке недели: процент выполненного и даты недели.

### 5.3 Календарь

- Сетка 16 недель на 7 дней.
- Цвет дня: всё сделано, сделано частично, лёгкий день, пропущен, выходной, впереди.
- Нажатие на день открывает его в «Плане».
- Строки недель помечены фазой, буферные недели выделены, в конце блоков 4, 8, 12, 16 показан крупный приз.

### 5.4 Трекер

- Таблица всех задач. Фильтры: тип, неделя, статус (не начата, в работе, к повторению, закрыта).
- В строке: название со ссылками, сложность, последняя попытка, следующее повторение, ключевая идея.
- Карточка задачи: история попыток, добавление попытки, ключевая идея, заметка.
- Счётчики сверху по типам: сделано из запланированного.

### 5.5 Призы

- 16 карточек: неделя, название, уровень, статус (заблокирован, доступен, получен).
- Кнопка «Получил» доступна только у доступных призов.
- Для крупных призов показано, сколько недель блока закрыто.

### 5.6 Журналы

Три вкладки: моки, истории для behavioral, подачи в компании. Простые редактируемые списки, заготовки берутся из `plan.json` при первом запуске.

### 5.7 Ресурсы и настройки

- Ресурсы: список из `plan.json`, основные отмечены.
- Настройки: дата старта, экспорт состояния в файл JSON, импорт из файла, сброс с подтверждением.

## 6. Правила

Вся логика лежит в чистых функциях в `src/domain/`, без зависимости от React. На неё пишутся тесты.

### 6.1 Повторения

Берётся последняя попытка задачи и число чистых попыток `cleanCount` за всё время.

| Последний исход | Следующее повторение |
| --- | --- |
| `failed` | через 1 день |
| `hint` | через 3 дня |
| `clean`, `cleanCount` = 1 | через 7 дней |
| `clean`, `cleanCount` = 2 | через 21 день |
| `clean`, `cleanCount` ≥ 3 | задача закрыта |

- Задача стоит в очереди, если дата повторения не позже сегодняшней и задача не закрыта.
- Способ повторения: «Устно, 3-5 мин», если последний исход `clean`, иначе «Решить заново».
- Числа брать из `plan.rules.review`, не зашивать в код.

### 6.2 Отметка сессий

- Сессия с `itemId` считается сделанной, если у задачи есть хотя бы одна попытка. Отдельной отметки у неё нет: пользователь добавляет попытку прямо из сессии.
- Остальные сессии отмечаются вручную: `done`, `light` или `moved`.
- Кнопка «Отметить день» ставит `done` всем неотмеченным ручным сессиям дня.
- Сессии с `optional: true` и блоком `rest` в подсчёты не входят.

### 6.3 Закрытие недели

Неделя закрыта, когда каждая обязательная сессия либо сделана через задачу, либо имеет статус `done` или `light`. Статус `moved` неделю не закрывает.

### 6.4 Призы

- Малый приз (`small`) доступен, когда закрыта его неделя.
- Крупный и финальный (`big`, `final`) доступны, когда закрыты все четыре недели блока: 1-4, 5-8, 9-12, 13-16.
- Приз не сгорает: неделю можно закрыть позже, и приз станет доступен.

### 6.5 Стрик

- Считаются подряд идущие плановые дни, в которые сделана хотя бы одна сессия или добавлена хотя бы одна попытка.
- Выходные по плану (блок `rest`) стрик не прерывают и не увеличивают.
- Сегодняшний день не прерывает стрик, пока не закончился.
- Показывать текущий стрик и рекорд.

### 6.6 Предупреждение о нагрузке

Если за последние 14 дней больше половины плановых дней отмечены как `light`, показать на экране «Сегодня» совет снизить нагрузку.

## 7. Этапы

Каждый этап заканчивается рабочей сборкой и отдельным коммитом.

### Этап 1. Просмотр плана

- Каркас проекта, типы, загрузка `plan.json`, навигация.
- Экраны «Сегодня» и «План» в режиме чтения, все ссылки кликабельны и открываются в новой вкладке.
- Скрипт проверки ссылок (раздел 8).
- Деплой на Vercel.

Готово, когда: открываю сайт с телефона, вижу сегодняшние сессии и могу перейти по любой ссылке.

### Этап 2. Прогресс и призы

- `UserState`, `StorageAdapter`, модуль правил 6.1-6.4 с тестами.
- Отметка сессий, добавление попыток, закрытие недели.
- Экран «Призы», прогресс недели на «Сегодня».

Готово, когда: отметил все сессии недели и решил её задачи, неделя стала закрытой, приз доступен, после перезагрузки страницы всё на месте.

### Этап 3. Трекер и заметки

- Экран «Трекер», карточка задачи, очередь повторений на «Сегодня».
- Ключевая идея и заметка к задаче, заметка дня.

Готово, когда: задача, решённая неделю назад, появляется в очереди с правильным способом повторения.

### Этап 4. Календарь, стрик, журналы

- Экран «Календарь», стрик, предупреждение о нагрузке.
- Журналы, ресурсы, настройки с экспортом и импортом.
- Экспорт расписания в файл `.ics` для импорта в календарь: одно событие на день с суммой минут и списком сессий.

Готово, когда: экспортировал состояние, сбросил, импортировал, и всё восстановилось.

## 8. Проверка ссылок

Часть адресов в `plan.json` собрана по шаблону сайта и помечена `confidence: "pattern"`. Это задачи LeetCode, вопросы GreatFrontEnd, статьи MDN, web.dev и react.dev.

На этапе 1 написать скрипт `scripts/check-links.ts`:

- Обходит все ссылки в `weeks`, `items`, `resources`.
- Делает запрос к каждому адресу с ограничением параллельности и задержкой.
- Печатает список адресов с ответом не 2xx и не 3xx.
- Ссылки поиска YouTube и сайты, которые блокируют автоматические запросы, пропускает и перечисляет отдельно для ручной проверки.

Битые адреса исправить в `plan.json` вручную: найти правильный на сайте и поменять `confidence` на `checked`. Вопросы GreatFrontEnd удобно сверять со списком `https://www.greatfrontend.com/questions`.

## 9. Качество

- Доступность: семантическая разметка, управление с клавиатуры, видимый фокус, подписи у кнопок-иконок.
- Никаких внешних запросов во время работы: приложение полностью статическое.
- Состояние сохраняется после каждого изменения. Повреждённые данные в хранилище не должны ломать приложение: показать предложение импортировать резервную копию или начать заново.
- Даты считать в локальном часовом поясе, без времени.
